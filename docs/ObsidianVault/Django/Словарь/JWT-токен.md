**JWT** (Json Web Token) — ключ аутентификации пользователя. Используется для запросов к защищенным методам API.

#### Термины
- Идентификация — процесс получения идентификатора пользователя: логин / e-mail /id

- Аутентификация — подтверждение личности пользователя (с помощью пароля, отпечатка пальца, и т.п.)

- Авторизация — предоставление прав пользователю, выдача токена

- Валидация — процесс проверки «куска» информации на соответствие требованиям программы, или просто на совпадение с копией, хранимой в базе данных.

- Токен — ключ аутентификации пользователя

- Credentials — учетные данные пользователя: логин, пароль, google id, и т.п.

- БД — база данных

- Клиент — уровень представления данных (см клиент-серверная архитектура). Имеет графический интерфейс для взаимодействия с пользователем. пример: веб-сайт в интернете.

- Сервер — уровень получения и обработки данных (см клиент-серверная архитектура). Не имеет графического интерфейса, принимает запросы от клиентов через API.

- API — Application Program Interface, набор команд, позволяющий обратиться к приложению

- Метод API — конкретная команда, позволяющая обратиться к приложению

- Публичные методы API — те, которые доступны без аутентификации пользователя, например: главная страница сайта в интернете.

- Защищенные методы API — требующие обязательной аутентификации пользователя, например: личный кабинет пользователя на сайте.

- Эндпоинт — url адрес метода API в интернете

## 🧠 Зачем это нужно

Без JWT:

- каждое обращение к API требует сессии и cookies;

- веб и мобильные клиенты должны хранить логин/пароль (небезопасно);

- нет единой схемы авторизации для внешних интеграций.


С JWT:

- доступ к API можно давать внешним приложениям без логина/пароля;

- токен можно быстро проверить без обращения к базе (он **сам себя подписывает**);

- легко масштабировать — серверы просто проверяют подпись токена;

- можно использовать единый механизм авторизации для SPA, мобильных и микросервисов.


## ⚙️ Как это работает

JWT (JSON Web Token) — это **не часть Django**, а **общий стандарт RFC 7519**.
Django (через `simplejwt`) просто реализует его.

Токен состоит из **трёх частей**, разделённых точками:

```json
xxxxx.yyyyy.zzzzz
```

1. **Header** — метаданные, обычно:

    `{"alg": "HS256", "typ": "JWT"}`

2. **Payload** — полезная нагрузка (кто пользователь, срок жизни и т.п.):

    `{"user_id": 42, "exp": 1760000000, "token_type": "access"}`

3. **Signature** — подпись, вычисленная с помощью `SECRET_KEY`.
    Она защищает от подделки токена.


При каждом запросе Django делает:

1. Декодирует токен;

2. Проверяет подпись (`SECRET_KEY`);

3. Проверяет `exp` (срок действия);

4. Извлекает `user_id` и подставляет `request.user`.

## 🔁 Access vs Refresh

- **Access Token** — живёт недолго (обычно 5–60 мин). Используется для авторизации.

- **Refresh Token** — живёт дольше (дни или недели).
    С его помощью можно запросить новый access без логина/пароля.


Когда срок access истёк, клиент делает:

`POST /api/auth/token/refresh/ {   "refresh": "<refresh_token>" }`


# Резюме:

### Что такое JWT
JSON Web Token — стандарт авторизации без сессий. Токен состоит из:
1. Header — алгоритм подписи
2. Payload — данные пользователя и срок действия
3. Signature — подпись для проверки подлинности

### Как это работает
1. Клиент отправляет логин/пароль → получает пару токенов.
2. При каждом запросе отправляет `Authorization: Bearer <access_token>`.
3. Сервер проверяет подпись и срок действия токена.
4. Если срок истёк — клиент обновляет `access` через `refresh`.

### В Django
Пакет: `djangorestframework-simplejwt`

```python
REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": [
        "rest_framework_simplejwt.authentication.JWTAuthentication",
    ],
}
```

## Преимущества

- Stateless авторизация (без сессий)

- Масштабируемость

- Простота интеграции (SPA, мобильные клиенты, API)

- Безопасность (подпись HMAC или RSA)


## Недостатки

- Нельзя отозвать токен без отдельного механизма (например, blacklist)

- Токен хранится на клиенте (нужен контроль безопасности)

```bash

curl -X POST http://127.0.0.1:8000/api/auth/token/ \

```
