## Где «стоп» (минимальный DoD скелета)

Я бы зафиксировал «готово», когда:

1. **CI** делает: `lint → tests → build docker → smoke /health`.

2. **README**: как поднять локально/в докере, как гонять тесты, ссылки на `/api/docs`, `/metrics`, бейджи build/coverage.

3. **Логи/метрики**: структурные логи (JSON) + базовые графики в Grafana (HTTP RPS/p95, 5xx).

4. **Безопасность по умолчанию**: CORS, SECURE_* заголовки в prod, SECRET_KEY/DSN из env, закрытый Swagger в prod по флагу.

5. **Тесты**: happy-path API + пара failure-кейсов, ≥70% coverage (у тебя есть), один e2e smoke.


Если чего-то из этого ещё нет — добьём точечно. Это часы, не недели.

## Что **не** подключаем сейчас

- Kafka/RabbitMQ. Тебе пока **не нужны**: Redis+Celery покрывают все текущие паттерны. MQ добавим только если появятся требования: массовые события, ретраи с DLQ, стрим-обработки, строгая доставляемость/партиции.

- Sentry self-hosted. Тяжелый. Для скелета можно отложить. Если захочешь — начни с облака (бесплатный tier) позже.

- Elasticsearch/ClickHouse/MinIO и т.п. — только когда появится use-case.


## Что можно добавить «для шлифовки» (по желанию, быстро)

Приоритет по выгоде/времени:

1. **Бейджи в README** (build, coverage).

2. **Smoke в CI**: `docker compose up -d` + `curl http://web:8000/health` (200).

3. **Структурные логи** (логгер DRF + request_id в middleware).

4. **Role/Permission модель** (простая RBAC: Admin/Manager/Viewer) — 2–3 эндпоинта с разными правами.

5. **Idempotency-Key** для одного POST (чтобы показать продакшн-паттерн).


Этого достаточно, чтобы рекрутер/техлид увидел: проект поднимается, документирован, наблюдаем, тестируем, есть базовые практики надёжности/безопасности.

## План на ближайшие 2–3 сессии

1. **README бейджи** и мини-таблица эндпоинтов (5–10 строк).

2. **CI smoke** (docker build + curl /health).

3. **Логи JSON + request_id** и один график 5xx в Grafana.

4. (Опционально) RBAC на 1–2 ручках.


Если хочешь, начнём прямо с пункта 1 (дам готовые markdown-сниппеты под твой репозиторий) или с CI-smoke (готовый job для `ci.yml`).
