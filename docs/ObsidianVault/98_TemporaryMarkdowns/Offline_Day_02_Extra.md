## 1️⃣ Git: базовые команды и принципы
**Цель:** уверенно работать с git без IDE, понимать, что происходит “под капотом”.

### 📋 Команды для практики
```bash
git status
git add .
git commit -m "feat: описание"
git log --oneline --graph
git diff
git restore <file>
git checkout -b feature/dev_setup
git merge feature/dev_setup
git push origin main
git stash / git stash pop
```

### 💡 Что нужно зафиксировать в Obsidian
- Что такое **commit**, **branch**, **HEAD** и **remote**
- Чем отличается `merge` от `rebase`
- Как откатить последний коммит (`git reset --soft` / `--hard`)
- Что делает `.gitignore`

🧩 *Практика:* создай “игровой репозиторий” (`git init test_repo`) и потренируйся на нём.

## 2️⃣ pre-commit: что это и зачем
**pre-commit** — фреймворк для автоматического запуска линтеров/форматтеров перед коммитом.

### 🔍 Как работает
- Читает `.pre-commit-config.yaml`
- Перед каждым `git commit` запускает набор скриптов (“хуков”)
- Если хотя бы один hook возвращает ошибку — коммит блокируется

### 💡 Зафиксировать в Obsidian
- Что делает `pre-commit install`
- Как выполнить все проверки вручную: `pre-commit run --all-files`
- Как очистить кеш: `pre-commit clean`
- Как обновить хуки: `pre-commit autoupdate`
- Что значит каждая секция в `.pre-commit-config.yaml`

## 3️⃣ Хуки (black, isort, flake8, pre-commit-hooks)
**Цель:** понимать, что делает каждый инструмент.

| Хук | Назначение | Проверяет / Исправляет |
|------|-------------|------------------------|
| `black` | автоформатирование кода | выравнивание, кавычки, длина строки |
| `isort` | сортировка импортов | группировка `stdlib`, `thirdparty`, `local` |
| `flake8` | линтинг (PEP8) | стиль, пробелы, неиспользуемые импорты, ошибки |
| `pre-commit-hooks` | мелкие проверки | конец файла, пустые строки, запрет `print()` |

### 💡 Практика
1. Отключи интернет, открой `.pre-commit-config.yaml`
2. Пройди по каждому `repo:` и пойми — что делает
3. Попробуй специально нарушить стиль (добавь `print()`, не тот отступ, двойной импорт)
4. `pre-commit run --all-files` и посмотри результат

## 4️⃣ Redis — брокер и кеш
Redis — это **in-memory key-value база**, которая используется Django в двух ролях:

| Использование | Что делает |
|----------------|------------|
| **Кеш** | хранит результаты запросов / сессии / throttle DRF |
| **Брокер задач (Celery)** | очередь задач между Django и воркерами |
| **Pub/Sub** | реальное время, WebSocket-события (каналы, уведомления) |

### 🔍 Основные команды
```bash
redis-cli
ping                # проверка соединения
SET key value
GET key
DEL key
KEYS *
FLUSHALL
```

### 💡 Для понимания
- Redis хранит данные в оперативной памяти — мгновенно, но не навсегда
- Ключи = строки, списки, множества, хеши
- Django подключается к Redis через `django-redis`
- Celery использует Redis как “очередь” — брокер сообщений между продьюсером (Django) и воркером (Celery)
